# AGENTS.md — `sample-data/`

Raw, unedited field recordings used by the AIS tutorial. Everything in this
tree is *input data*; nothing here is generated by the tutorial code. The
tutorial copies **small excerpts** of these files into `../data/` so that the
chapters stay readable; when you need a new example, pull it from here and keep
the excerpt as short as possible.

Most files were logged by Kurt Schwehr and collaborators at the UNH Center for
Coastal and Ocean Mapping (CCOM) between 2006 and 2011, using a small Python
serial logger (`serial_logger.py`). That logger produces a recognisable file
shape that you will see over and over:

```
# START LOGGING UTC seconds since the epoch: 1197072047.98
# SPEED:       38400
# PORT:        /dev/tty.iBT-GPS-SPPslave-1
# TIMEOUT:     300.0
# STATIONID:   plane_to_sd
# DAEMON MODE: False
$GPGGA,...*4C,rplane_to_sd,1197072048.14
```

* Lines starting with `#` are logger comments (start banners, `# MARK:`
  timeout markers, or in the oldest files a `# <epoch>` line *before* each
  sentence).
* Each NMEA sentence is followed by two extra comma-separated fields in the
  "USCG format": `r<station-id>` and the UNIX receive time in seconds.
  Older logs (2007) only append the timestamp, e.g. `...*3C,1179352435.36`.
* Many files have `\r\r\n` or `\r\n` line endings. Treat `\r` as whitespace.
* Files are frequently truncated mid-line at the end (the logger was killed).

## Which directory answers which question?

* **Plain NMEA 0183 GPS sentences** → `gps-itrek/gps.log.2007-12-08` (small, 1 700 lines, includes a flight at 12.5 km altitude).
* **AIS position reports 1/2/3 with USCG `s/d/T/x/r/time` metadata** → `RightwhaleAisProject/20081013.log` (huge) or `sbnms/2008/data/*.ais.unique` (type 5 only).
* **Base station report (4) and DLM (20)** → `2007hydro/va-portsmouth-sr162-2007-05-1[578]`, `AISmisc/2008-03-27-bs-send-test/bs1-2008-03-27` (`!BSVDO`).
* **Class B (18, 19, 24)** → `tide3/ais/ais-2011-05-2*`, `AISmisc/200905-Cocheco-classb-config/`, `AISmisc/classb.uscg.19.nmea`.
* **AtoN report (21)** → `2010-11-l3-aton/ccom-sr162g-2010-09.aivdm` (`E…` payloads).
* **Binary messages (6, 8) and ASM payloads** → `RightwhaleAisProject/` (whale notices, 8/366/34), `2007hydro/` (8/55/58, 8/366/…), `tide3/ais/ais-2010-12-*` (8/366/56 and 57 encrypted), `tide1/ais/*` (assorted, often corrupt).
* **Interrogation (15), assignment (16), channel management (22)** → `2007hydro/va-portsmouth-sr162-*`, `2007hydro/protec-util12007-05-14`.
* **Own-ship `!AIVDO`, alarms `$AIALR`, text `$AITXT`** → `2007hydro/protec-util12007-05-14`, `AISmisc/2008-03-24-sbnms-whale-test/log-rm808.2008-03-24`.
* **BBM/ABK (sending binary messages from a transponder)** → `RightwhaleAisProject/20081003-AIS/AIS_whale`, `…/whale.txt`, `…/sample message*.txt`.

## Caveats for anyone reusing this data

* The `nhjel` receiver in `tide1/` was marginal: a large fraction of its
  `!AIVDM` lines are truncated or bit-corrupted yet still carry a *valid*
  checksum (the receiver computed the checksum over garbage). Always validate
  payload bit lengths against the message type before trusting a decode.
* Some logs contain binary junk (`\x00` bytes, transponder boot banners).
  Open them in binary-tolerant mode (`errors="replace"` in Python).
* `.bz2` files in `tide3/ais/` duplicate same-day plain files; prefer the
  plain file.
* MMSIs, vessel names and positions are real historical data (2006–2011).
  Do not treat them as current.

## Rules

* Do **not** edit, reformat or re-encode anything under `sample-data/`.
* Do **not** add generated output here; use `../data/` for excerpts and
  `../tests/expected/` for decoder output.
* Keep excerpts copied into the tutorial small (tens of lines), and name the
  source file and line numbers in the chapter text.
